# 系统升级控制台

状态：仓库已实现独立控制台、主应用维护门禁、Actions 产物校验、升级与恢复流程；生产尚需安装、填入实际配置并完成隔离环境演练。本文件描述当前代码，不表示现网已上线。

## 1. 目标与目录

升级控制台位于仓库 `upgrade-console/`，作为 `interview-reader-blueprint` 的 Maven 子项目构建为独立 JAR，独立监听本机端口；Vue
界面位于 `upgrade-console/frontend/`，本地 H2 保存状态和日志。主后台菜单仅使用 Actions 仓库变量 `UPGRADE_CONSOLE_URL`
在构建时注入的 HTTPS 地址；未配置时升级入口不可打开。主 JAR 停止、Flyway 失败或数据库不可用时，控制台仍能显示已持久化的发布状态、备份
ID 和操作事件。

| 路径                                  | 用途                                                          |
|---------------------------------------|---------------------------------------------------------------|
| `deploy/daemon.sh`                    | 主应用单进程启停；升级流程调用 `start` 和 `stop-gracefully`。 |
| `deploy/conf/application.env.example` | 主应用脱敏配置，包含维护门禁路径与内部令牌。                  |
| `deploy/upgrade-console/`             | 控制台和 MySQL 客户端凭据的脱敏模板。                         |
| `deploy/systemd/`                     | 独立控制台进程管理示例。                                      |
| `deploy/nginx/`                       | 主站与独立升级站点代理示例。                                  |
| `docs/operations/runbook.md`          | 现网安装、权限、演练和故障处置。                              |

生产当前已确认 `INTERVIEW_READER_STORAGE_DIR=/opt/ireader/data`，主脚本位于 `/opt/ireader/daemon.sh`。控制台
`UPGRADE_DATA_DIR` 必须与实际存储根一致。数据库对象键使用相对路径；备份完整数据根，包括根层哈希目录和 `import-sources`
，不只备份其中一个子目录。`data/target/pdfbox-font-cache` 可重建，但现阶段完整备份以免漏文件。

## 2. 发布来源与认证

`.github/workflows/verify.yml` 在 main 分支通过前后端检查后，归档正式主 JAR、对应 SHA-256 清单和独立控制台 JAR。上传主 JAR
时必须提供 Actions 运行 ID；控制台从 GitHub API 核对运行已成功结束、由 main 分支 push 触发、工作流名为 `verify`
，再读取该运行的校验产物，比对服务端计算的 SHA-256。正式主 JAR 同时嵌入该运行的提交号，控制台在新进程就绪后核对提交号才开放写入。开始发布前会再次执行相同核验。过期、失败、非
main 或内容不符的产物不能发布。本地打包 JAR 不能单独作为正式发布来源。

正式版本在上述 `verify` 运行成功后，为同一提交推送 `vX.Y.Z` 标签。`publish-release` 工作流从该运行下载同一批主 JAR、控制台
JAR 和校验文件，核对主 JAR 的 SHA-256 后发布 Release 附件及 `SHA256SUMS`，并在备注中记录 Actions 运行 ID。Release
只改变下载位置；控制台仍按原 Actions 运行 ID 和校验产物验收。Actions 校验产物过期后，该 Release 附件不能作为新的升级上传来源。

控制台使用独立管理员密码和 HTTPS Origin 校验，不复用主站会话。Nginx 示例限制 VPN/内网访问，控制台本身只监听 `127.0.0.1`
。主应用的 `/internal/upgrade/status` 只接受本机请求和不少于 32 字符的共享令牌，报告维护门禁、在途写请求、导入与删除任务及即时指标。主站和升级站点不能共用根作用域
Service Worker。

## 3. 健康面板与升级门禁

控制台按 15 秒间隔请求主应用的总体健康、存活、就绪和内部排空状态；升级阶段与命令日志经 SSE 即时推送，页面展示：

- 存活、就绪、数据库和磁盘空间是否为 `UP`；
- 正在执行的写请求，以及待排空的导入、删除任务；
- JVM 已用内存、活跃数据库连接和 HTTP 平均延迟；
- 最近检查时间、升级阻断原因及当前操作阶段。

总体健康、存活、就绪、数据库、磁盘和内部接口全部正常，且维护路径、数据根、数据库名与实例身份可核对、没有既有维护门禁时，发布按钮才可用。服务端在创建发布前也重新预检，不依赖按钮状态。主应用停机时健康项显示不可用，独立控制台继续展示本地状态。

跨重启维护标记为 `/opt/ireader/tmp/upgrade.maintenance`。主应用拦截新的不安全 `/api/` 请求并返回
503；已进入的写请求与导入、删除任务计入排空。重启后删除 Worker
在标记存在时不会自动恢复；标记移除后会定期恢复持久任务。定时墓碑清理也受门禁控制。只有控制台在确认发布或恢复版本就绪后才移除该标记。

## 4. 唯一发布入口与顺序

单机一次只允许一个升级或恢复操作；独立状态目录持有进程锁，H2 事务持久化已验证版本、操作状态、阶段事件及本次 `daemon.sh`
的标准输出和错误输出；首次启动自动导入旧 `state.json` 并保留 `state.json.migrated`。正常发布按固定顺序执行：

1. **预检**：复核 Actions 产物、主应用健康、目录、数据库客户端、主应用与备份连接的 MySQL 实例身份和备份目标空间。
2. **停写**：原子写入维护标记；主系统拒绝新写入。
3. **排空**：连续检查写请求、导入与删除任务为零，超时中止。
4. **备份**：此时主进程仍运行但不再写数据。使用 `mysqldump --single-transaction` 备份指定 MySQL 库，同时复制完整数据目录、旧
   JAR 和配置文件；生成 SHA-256 清单。数据库和文件使用同一个操作 ID 作为恢复点。
5. **进程停止**：调用 `daemon.sh stop-gracefully`，不允许超时后强杀并继续切换。确认主端口关闭。
6. **切换与迁移**：把已核验 JAR 复制到主目录同一文件系统，再原子替换固定的 `interview-reader.jar`；调用 `daemon.sh start`。新
   JAR 自行运行 Flyway。
7. **就绪检查**：检查总体、存活、就绪、数据库、磁盘及跨重启门禁。全部通过后才移除标记、恢复写入并记录成功。

`daemon.sh start` 的两秒进程检查不是发布成功依据。旧版需先通过一次手动引导安装维护门禁和新脚本；此后生产升级统一由控制台发起，手工脚本操作仅作故障处置。

## 5. 失败、回滚与中断

- 停机前的预检、排空或备份失败：如果旧版就绪，解除维护标记并记录失败；若无法确认，保留标记并标记 `NEEDS_OPERATOR`。
- 停机后切换、Flyway 启动或就绪检查失败：保持停写，停止新进程，校验同批次备份，恢复数据库、数据文件和旧
  JAR，再启动旧版并检查就绪。全部成功才解除门禁并标记 `ROLLED_BACK`。
- 控制台中断：尚未设置维护门禁的预检操作记为失败；其余未完成操作在重启后标记为 `NEEDS_OPERATOR`
  ，不猜测成功，也不自动解除门禁。页面允许对有完整备份且门禁仍在的操作执行明确确认后的恢复；备份尚未完成的中断操作只能在旧版健康、任务已排空且标记属于该操作时解除停写。
- 发布成功后的人工恢复：操作员选择历史成功发布的备份并确认可能丢失之后的写入。控制台先对当前状态制作新备份，再停进程、恢复目标版本；恢复目标失败时尝试恢复本次操作开始前的状态。任何恢复失败均保持维护状态，等待人工处理。

备份恢复会执行数据库 DROP/CREATE，需要专用、受限的数据库凭据。所有备份保留在控制台私有目录；代码目前不自动清理旧备份。控制台与主
JVM 当前同为 `ireader` 用户，尚未拆分为主机级独立权限执行器。上线前应结合主机权限评估，并限制升级站点与服务器登录。MySQL
同构副本迁移演练仍是上线步骤，当前代码不自动运行生产副本验证。

## 6. 页面与接口

| 方法与路径                                                 | 用途                                               |
|------------------------------------------------------------|----------------------------------------------------|
| `GET /api/overview`                                        | 兼容旧客户端的完整概览。                           |
| `GET /api/dashboard`                                       | 首页健康摘要、最近操作与日志游标。                 |
| `GET /api/releases`、`GET /api/releases/{id}`              | 搜索、分页查看已验证升级包与详情。                 |
| `GET /api/releases/{id}/operations`、`GET /api/operations` | 分页查看升级包或全部操作记录。                     |
| `GET /api/operations/{id}/feed`                            | 从 H2 分页读取阶段与启停命令日志，支持断线后查看。 |
| `GET /api/feed/stream`                                     | SSE 推送新增记录，支持 `Last-Event-ID` 游标续传。  |
| `POST /api/releases`                                       | 上传 JAR 与 Actions 运行 ID，校验并暂存。          |
| `POST /api/releases/{id}/deployments`                      | 重新核验并发起单次发布。                           |
| `GET /api/operations/{id}`                                 | 查询阶段、状态、备份 ID 与事件。                   |
| `POST /api/operations/{id}/recover`                        | 中断操作的同批次备份恢复，需明确确认。             |
| `POST /api/operations/{id}/abort`                          | 备份完成前中断时，核验旧版并恢复写入。             |
| `POST /api/recoveries`                                     | 成功发布后的人工恢复，需明确确认数据覆盖。         |

控制台首页紧凑展示健康依据、运行指标及最近操作的真实阶段和日志。上传升级包、升级包列表、操作记录分别在独立页面；列表与操作详情使用同一持久日志源。SSE
只包含控制台阶段事件及本次启停命令输出，不读取主程序原始运行日志。Nginx 的 `/api/feed/stream` 代理需关闭缓冲并允许长连接。

详细安装、配置权限和演练步骤见[生产运行手册](../operations/runbook.md)。
